The production pipeline is genuinely wired

validate → load_segments → constraints → translate → gates(quality) → refine ↻ reflexion(back-translate) → finalize → END ↑ deterministic defect gate ↑ semantic-drift score ↑ audit event + real output_hash
  • Quality gate runs per segment via check_segment — numeric / unit / negation / ghost-number / glossary / forbidden-term / PII / complexity / gross-omission / date-format, with a CRITICAL·MAJOR·MINOR taxonomy (A2 deterministic, not in the LLM prompt).

  • Back-translation computes a real per-segment semantic-drift score (embedding cosine), persisted to the scorecard.
  • Audit — quality scorecard and job-finalize events emit to the v2 chain.

Reversibility: two-way · Owner: Audit & Validation · Worksheet: .context/loops/TMX-3213.md

TMX-DRIFT-GATE — Back-translation drift becomes an enforced review gate

Reversibility: two-way · Owner: Agent & AI + Quality · Worksheet: .context/loops/TMX-DRIFT-GATE.md

New pure assess_reflexion() turns the measured per-segment fidelity score into a routing signal. When a genuinely-assessed segment scores below the threshold (default 70/100), finalize_job escalates TRANSLATED → IN_REVIEW (one-directional — never auto-passes, never downgrades a held job) and records the reason in the audit payload.

Safety design: the 0.0 no-API-key sentinel and unscored segments are excluded (> 0.0 required to count) so keyless / test jobs are not falsely held — the gate fails toward human review only on a real signal (A3).
