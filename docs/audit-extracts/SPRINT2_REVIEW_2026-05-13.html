3. Incremental value & benefit

Trust

Defensible audit evidence

The chain moved from "string concat, hope nobody looks" to a domain-separated, independently-verifiable, externally-anchored ledger that now carries live pipeline events. This is the wedge against Phrase / Smartling / DeepL — none of them can hand a pharma reviewer a tamper-evident chain of custody.

Robustness

Concurrency & boot safety

Two race conditions (circuit breaker, quality-gate singleton) closed with reproduced-then-fixed tests. The app can no longer boot into production with default secrets or auth disabled. These are silent-failure modes removed, not features added.

Compliance

Human-in-the-loop integrity

Auto-promotion of learned rules is gone — every rule that goes live now carries a signed approval and an audit event. That's the difference between "the AI changed its own behaviour silently" and "a qualified person approved this change," which is exactly what an Annex-11 reviewer checks.

Stability

Anti-drift machinery

The drift + worktree audits mean the worksheet board can no longer lie about what's shipped. A fresh clone now reproduces the claimed state — the precondition for any honest compliance posture.

The compounding benefit: every loop ran through the same 8-stage discipline (spec → failing test → code → red-team → push) and left a worksheet behind. The result is that the evidence of how each fix was made is itself audit-grade — which is the meta-product TransMax sells.

5. Architecture judgment — is LangGraph required?

You asked whether a more optimised agentic implementation is possible and whether LangGraph is required. My judgment, recorded in ADR-0002 (docs/decisions/0002-langgraph-necessity.md):

ObservationDetail
Actual topology8 nodes, 1 conditional edge (gates → refine | reflexion), 1 cycle (refine → gates). A TypedDict state object.
LangGraph features usedStateGraph, add_conditional_edges, add_edge. That's it.
LangGraph features not usedCheckpointing, streaming, human-in-the-loop interrupts, sub-graphs, tool-calling integration — none.
LangChain wrappersChatOpenAI / SystemMessage are largely dead weight — app.services.llm already abstracts the provider.

Decision: Keep LangGraph for the pilot. The orchestration this codebase needs could be a ~80-line plain async Pipeline class (a while iteration_count < MAX loop + a 3-branch if), which would shed ~200 LOC and 2 dependencies. But swapping it mid-pilot would disturb the eval harness, the @traced wiring, and ~30 graph tests — for marginal gain — while the audit ledger is the genuine critical path. The right move is to defer the swap to v3.5 via a planned worksheet TMX-3500-ARCH-LANGGRAPH-REVIEW, and meanwhile drop the unused LangChain aliases as cheap bookkeeping.

Why this is the disciplined answer: "rewrite the orchestrator" is a classic while-I'm-here anti-bloat trap. The state is already a plain TypedDict with no LangGraph-specific persistence, so the future swap stays cheap — meaning there is no penalty for waiting. We bank the option without paying for it now.

7. Next epics / loops I propose — and why

Ordered by value-to-the-outcome. Each is a candidate loop with a clear pilot benefit; the first three are queued and ready to run now.

Epic E-A · Audit ledger completion

TMX-3110 Phase 2 → 4 + TMX-3105 + TMX-3109

What: (P2) a per-job v1↔v2 coverage audit script that catches any event the Phase-1 broad-except wrapper dropped; (P3) switch bundle-export & integrity reads to v2; (P4) retire v1 emits. Plus TMX-3105 verifier HTTP endpoint and TMX-3109 historical v1→v2 backfill.

Why / value: Until consumers read v2 and v1 is retired, we maintain two chains and can't claim v2 is the system of record. This is the straight-line path to a defensible (not just present) audit ledger — the core differentiator. Trust ✚✚✚ · Robustness ✚✚

Epic E-B · Reviewer-facing verification

TMX-3105 — "Verify this chain" endpoint + UI badge

What: expose AuditVerifierV2 at /api/v1/audit/{job_id}/verify and render a verified-state badge on the reviewer surface.

Why / value: A reviewer who can click "verify" and watch the chain re-compute live is worth more in a sales/pilot demo than any amount of backend correctness they can't see. Trust signals must be visible where a regulator looks (TransMax addendum). Trust ✚✚✚ · End-user value ✚✚

Epic E-C · Defensible PII

TMX-3805 — Presidio replaces regex PII

What: swap the regex-only, sequential-pass PII service for Microsoft Presidio (or Comprehend Medical) with proper entity recognition.

Why / value: Pharma documents carry patient identifiers. A regex PII filter that misses entities is a compliance liability, not a feature. This closes audit finding C-12 and removes a "we said we redact PII but actually we mostly don't" exposure. Compliance ✚✚✚ · Robustness ✚✚

Epic E-D · Regulatory pack → live evidence

TMX-3500 follow-ups — bind IQ/OQ/PQ to real audit events

What: generate the qualification documents from actual run + audit-chain evidence instead of static templates, with traceability links resolving to real event hashes.

Why / value: The pack is the artifact a CSV team signs. A template is a promise; a pack built from real evidence is the deliverable. This converts the scaffold into the thing that closes a pilot. Compliance ✚✚✚ · End-user value ✚✚

Epic E-E · Arch simplification (v3.5)

TMX-3500-ARCH-LANGGRAPH-REVIEW

What: replace LangGraph with a plain async Pipeline class; drop unused langchain_core / langchain_openai imports; centralise tracing.

Why / value: ~200 LOC and 2 dependencies removed, simpler onboarding, fewer CVE surfaces. Deliberately scheduled after the audit work because it's an optimisation, not a capability — and the cost of waiting is near-zero (per ADR-0002). Stability ✚✚ · Robustness ✚
