1 · The loop strategy we already follow

Every non-trivial ticket runs as a loop — an 8-stage unit of work captured in a worksheet at .context/loops/TMX-XXXX.md. A ticket is "Done" only when stage 8 closes with a pushed commit SHA. This is the discipline that produced the Sprint 2 chain (9/9 critical findings closed, 0 real regressions).

The 8 stages

1
Task — restate the ticket; blast radius; reversibility (one-way → human approval, two-way → ship); pre-mortem.
2
Spec — falsifiable acceptance criteria (AC-1, AC-2 …).
3
Design — approach + alternatives considered & rejected; ADR if non-obvious.
4
Code — surgical edits; file:line table.
5
Eval / Test — captured run output for tests + ratchet.
6
Red team — 22-item Tier-2 checklist + A1–A10 addenda audit.
7
Fix — anything red-team surfaced.
8
Deploy — commit (with Self-review block), push, update active_tasks.md. SHA on origin/main = Done.

The three gates (non-negotiable, checked before any "Done")

GateWhat it forces
G1 · Anti-bloat / valueBefore any net-new code, it must pass the 5-test rubric (functional depth · end-user value · trust · robustness · stability). If all five are "no", we don't build it — pick a smaller change or escalate to [Blocked].
G2 · Reproduce-the-failure (TDD)For any user-visible failure, reproduce it in a failing test/curl before claiming a fix. A test that documents a failure without changing the code that fixes it is not a completed ticket.
G3 · CompletionDid this commit change source that addresses the failure? Would a repro now succeed? If either is "no", status is [Blocked], not [Done].

The mechanical backstops (survive any context state)

  • Ratchet — 17 monotonic metric floors in ratchet/baseline.json; they only tighten, never loosen.
  • Pre-commit — ruff/format/mypy, quality gate (PRS ≥ 85), red-flag attestation, ratchet check, advisory drift + worktree audits.
  • CI — all of the above + tests + coverage + second-pass reviewer + eval harness.
  • Periodic 4-agent verify-audit — every ~10 loops: code-quality, pytest, vitest, spec-vs-delivery.
This is the strategy you asked me to keep using. Each loop below ("epics & loops to spawn") will run through these 8 stages and 3 gates, with its own worksheet and its own sub-agent context window. The sections that follow tell us what to put in the pipeline and why.

3 · The agentic pharma solution of the future

The market is splitting into two losing camps: pure-human LSPs (RWS, Lionbridge) — accurate but slow/expensive; and pure-MT/agentic platforms (Phrase, Smartling, Lilt, DeepL) — fast/cheap but cannot produce a defensible evidentiary record. TransMax wins the wedge neither can occupy: MT economics + a cryptographically defensible, Annex-shaped audit chain an inspector can sign off.

The regulatory calendar just did our marketing. EU AI Act high-risk obligations go live 2 Aug 2026; EMA's draft Annex 22 (AI in GMP) and the expanded Annex 11 (5→19 pages) codify confidence-thresholds, "undecided" flagging, feature-attribution, static-model/config control, and documented human-in-the-loop — which read like a product spec for TransMax. Incumbents must retrofit compliance; we can claim we were designed to the regulation.

What "agentic" means (vs CAT tool + MT)

A CAT+MT tool translates a segment when asked and waits. An agentic system owns the workflow — it plans, calls tools (TM/glossary/RAG), self-checks via reflexion, decides when it is confident, and escalates to a human only on the segments that need it. The market has agentic orchestration largely solved for localization. Nobody has solved agentic + evidentiary: every autonomous decision (which model, prompt version, confidence, why it escalated) recorded as tamper-evident, replayable evidence. That gap is the moat.

4 · Agents + humans: the cost/quality wedge

$0.15–0.30
/word — pure human (RWS/Lionbridge), top of range for regulated
$0.05–0.15
/word — MT post-editing (MTPE)
~40%
cost cut Intel achieved with HITL (Lilt), volume doubled
$0.08–0.12
/word — proposed TransMax blended target

The lever is "review only what's flagged," and the flagging is auditable.

  • vs pure-human LSPs: agent drafts ~90%, deterministic gates pass the safe segments, humans review only the flagged minority (low-confidence, safety-critical, novel terminology). You pay senior-linguist rates on ~10–20% of the wordcount, not 100% — approaching MTPE economics while delivering more defensible quality (every gate-pass is logged evidence an email chain never produces).
  • vs pure MT (DeepL): DeepL is cheap but produces zero evidentiary record, no oversight, no model card — unusable for a regulated submission. The buyer isn't comparing translation prices; they're comparing $0.10/word with an audit trail vs a six-figure CSV remediation and a slipped filing date.
  • The flywheel: editor corrections feed back as versioned re-qualified releases (Annex-22-safe), so the flagged fraction shrinks — human cost falls while quality rises. Competitors doing silent online learning fail the static-model test.

Pricing message: "MTPE economics, RWS-grade defensibility, and an inspection-ready evidence pack an LSP charges separately (or can't produce)." Undercut RWS 40–60%; premium over commodity MTPE justified entirely by the audit/validation deliverables.

5 · Full-document round-trip fidelity

Today TransMax is fundamentally text-in / text-out per element — no structured document model, no interchange format, no stable per-segment handle carried back to a precise position. This is both a fidelity problem and a live GxP correctness defect.

Current state

FormatInOutFidelityWhere it breaks
DOCXYesYesPartialText is stripped on ingest so inline boundaries (bold/italic/superscript/hyperlinks/field codes) are lost before translation; export re-distributes translated text across runs by word-count proportion — a heuristic guess. Footnotes collapse into the first <w:t>.
PDFYes (text)NoNoneExports a fresh blank DOCX — layout, fonts, images, tables, columns all lost. A mock-data fallback when real parsing is off (A3 risk).
XLSX / PPTXNoNo—Not supported; openpyxl/python-pptx not dependencies.
The A5 / TMX-3701 defect (unstarted): export matches translations by source-text content first (document_export.py:248-256), falling back to a re-counted order index. Two identical source strings ("N/A", "10 mg", repeated headers) collapse to one dict entry — a reviewer's edit to occurrence #2 can be silently replaced by occurrence #5's translation. A one-element traversal divergence shifts every subsequent segment off-by-one. On no-match it leaves source text in place silently (A3 violation). This breaks the GxP guarantee "an edit to segment X lands on segment X."

Target architecture — skeleton + extractable units (Okapi / XLIFF 2.1)

Upload ──► FILTER/EXTRACTOR ──┬─► SKELETON (file minus text; placeholders by id)
                              └─► UNITS (stable unit-id + source w/ inline <ph>/<pc> tags)
                                         │
                          TRANSLATION PIPELINE (existing LangGraph)
                          mask inline tags → translate → restore;  segment_id == unit-id (A5)
                                         │
                          MERGER (deterministic): walk skeleton, look up unit-id → inject
                          target, re-emit original format.  NO content/order matching.

Translate only the units; merge back by stable ID, never by content or position. Edit OOXML in place (keep runs as <ph> placeholders) instead of stripping text. Protect inline tags from the MT engine and validate they survive (a deterministic gate per A2). Merge failures raise + emit an audit event (A3 fail-loud).

6 · Prompts, token costs & guardrails

Strong bones, but no single governed LLM-call chokepoint. The prompt registry (A8) is genuinely built and good; the quality gates (A2) are deep and pharma-aware. But app/services/llm.py is a dumb singleton that records nothing, masks nothing, budgets nothing — so token accounting (A6), input PII protection, injection defense and per-job budgets are all absent or bolted on after the fact.

Built & good

Prompts (A8)

Versioned YAML store, frozen cached registry, semver latest, schema validation, and a content_hash per prompt — all shipped (TMX-3200/3201). Only gap: the hash is never written to the audit chain.

Deep & pharma-aware

Output guardrails (A2)

Numeric/ghost-number, dosage-unit, frequency (BID/QD), negation-flip, placeholder/table/symbol integrity, PII leak detection, deterministic "Iron Gavel" verdict. Stronger than generic NeMo/Guardrails-AI for pharma.

Live A8 violation

Audit snapshot lies

graph.py:159-160 hardcodes "model":"gpt-4o" and "prompts_version":"v1.0" — doesn't match the on-disk version and ignores the real content hash. A regulator flags this as a tech-doc inconsistency.

GDPR / Annex-11 gap

No input rails

Raw PII is sent to the external LLM — PIIService.mask is wired only as an output detector, never as an input rail. No prompt-injection screening. PII engine is regex-only (C-12).

The root cause & the fix: one governed gateway

Every gap traces to there being no chokepoint. Promote app/services/llm.py to the single governed gateway every LLM call must pass through:

caller(node, agent="translator") ─► app/services/llm.py  GOVERNED GATEWAY
  1 PromptRegistry.load(agent,ver) → system,user,content_hash      (A8)
  2 render(user, **vars)  — FAIL LOUD on missing {{var}}           (A3)
  3 INPUT RAILS: PII mask (reversible) · prompt-injection screen   (GDPR)
  4 BUDGET pre-check (job/tenant/org cap)                          (FinOps)
  5 model = router.pick(difficulty)                                (cost)
  6 call provider (cached prefix; batch tier)
  7 capture usage → cost via model_pricing (single source)        (A6)
  8 EMIT AUDIT EVENT {provider,model,version,prompt_ver,hash,
                      in_tok,out_tok,cost} BEFORE returning        (A1+A6)
  9 OUTPUT RAILS: PII unmask+rescan · Pydantic schema · QualityGate(A2)
 10 budget accumulate; if over cap → BLOCK loud                    (A3)

8 · How we run it — parallel sub-agents on the loop discipline

Each loop runs as its own sub-agent with its own context window (so we can go long without exhausting any single context), following the exact 8-stage / 3-gate discipline:

  1. Independent loops fan out in parallel (the ⚡ items) — multiple sub-agents in one batch, each owning one worksheet via the Owner: lock.
  2. Dependent loops run in sequence (the → items) — each waits for its predecessor's pushed SHA.
  3. Every loop self-verifies — failing-test-first (G2), red-team (stage 6), ratchet check, pushed SHA (stage 8).
  4. Every ~10 loops — the 4-agent verify-audit runs to catch drift before it compounds.
  5. One-way / customer-facing artifacts (E4 validation pack) — design brought to you for sign-off before shipping.
My proposed first move: spawn the E5 harness batch (7 independent loops in parallel) plus kick off E1's independent loops (TMX-3110 P2 coverage audit, TMX-3105 verifier endpoint, TMX-3107a S3 wiring) — and the most urgent E3 loop, TMX-3701 (the live GxP fidelity defect). That's a high-value parallel wave that needs no further input from you. The three Kapil-gated items (TMX-3000 history purge, TMX-3002 db de-commit, TMX-3013 Auth0) stay parked for your explicit go.
