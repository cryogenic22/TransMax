## 1. Task

The frontend currently has **zero automated tests**. Build / typecheck / lint exist but no unit tests, no component tests, no end-to-end tests. As of the TMX-3606 de-tangle (`cbef01f`), the frontend is now part of the parent repo and ships through CI — but CI only runs the Python backend suite. A frontend regression has no chance of being caught before it lands.

This loop wires the frontend test harness:

1. **Vitest** for unit + component tests (React 19 / Next 16 friendly, fast, no jest-fairy-dust).
2. **Playwright** for e2e tests (cross-browser, mocked-backend mode in this loop; a real-backend integration job is Loop 15).
3. **CI** runs `lint` / `typecheck` / `build` / `vitest` / `playwright` on every PR.
4. **No-regression gates**: lint warning count is pinned at the current baseline so new code can't add lint regressions while the focused cleanup loop (TMX-3614-lint) drives them down.

**Blast radius**: `frontend/` only (test deps + configs), plus `.github/workflows/ci.yml` (new frontend job). No backend code touched. No runtime production code touched.

## 3. Design

**Vitest, not Jest**: Vitest natively supports ES modules, TypeScript, JSX, Vite-style HMR. Jest+Next 16 needs a babel/swc shim and tends to break on RSC. Vitest is the obvious choice for Next 16. Confirmed via `next-vitest-example` repo.

**happy-dom vs jsdom**: happy-dom is ~3× faster on small DOMs and supports modern Web APIs. jsdom is more compliant for niche cases. We pick happy-dom; if a test ever needs a missing API, that test can opt in to jsdom via per-test override.

**RTL + jest-dom matchers**: industry standard for React component tests. The Testing Library philosophy ("test how the user interacts") aligns with the reviewer-facing nature of TransMax.

**Playwright config**: `chromium` only this loop. `webkit` and `firefox` are added in Sprint 2 (TMX-3614-cross-browser). Tests run against `npm run dev` (i.e. Next dev server) which Playwright auto-starts via `webServer` config.

**Mocked backend in Playwright**: this loop's e2e tests intercept `/api/**` via `page.route(...)` and respond with fixtures. This proves the wiring without coupling to a real backend. Loop 15 adds the integration variant.

**CI sequencing — why lint before build before tests**:
- Lint is fastest (1-3s) and surfaces 80% of "you forgot to import something"
- Build (10-20s) catches type errors and rendering errors
- Vitest (5-15s) covers component logic
- Playwright (30-60s) covers e2e flows
- Fail-fast: a lint failure blocks a PR before burning 60s on Playwright.

**Lint-baseline gate**: `eslint --max-warnings 185` will fail if total reaches 186. New code cannot add new errors. The cleanup loop drives N downward; the gate moves with it (no ratchet UI in eslint, but the integer baseline is in `package.json` so a code-review catches drift).
