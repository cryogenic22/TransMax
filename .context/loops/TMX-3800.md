## 1. Task

Per plan E5 + critical issue C-11 from the May 2026 review: `app/api/v1/translations.py:54` uses `text.split('.')` to break submitted text into segments. This is a known defect: it splits on every period, including those inside pharma abbreviations (`Dr.`, `mg.`, `e.g.`, `i.v.`), inside decimal numbers (`5.5 mg`), and inside ellipses. Each downstream segment is a partial sentence; gates fire false-positives; LLM context is truncated.

This loop installs the **skeleton + interface + regex implementation** for sentence segmentation. The interface is shaped so future loops can plug in NLTK Punkt, spaCy senter, or pharma-specific Pragmatic Segmenter without changing call sites.

**Blast radius**: every job submitted via `POST /api/v1/translations` with inline `text_content` — that's the SDK + REST entry point. Improvements visible immediately in the eval suite (no current test exercises this path though, so an explicit unit test suite is needed).

**Addenda**: A2 (deterministic gates depend on accurate segments), A5 (segments carry stable IDs — a real segmenter is a precondition).

## 3. Design

**Why regex first, NLP later**: NLTK Punkt requires `nltk.download('punkt')` which depends on network availability and a writeable cache directory; in a containerised deploy the data file would need to be vendored. spaCy is heavier still (model download per language). For the skeleton, regex with explicit abbreviation protection is enough to fix C-11; the interface is designed so a future loop can drop in a better backend without touching call sites.

**Algorithm**:
1. Replace each known abbreviation with a sentinel token (`Dr.` → `Dr`).
2. Replace each decimal number with a sentinel (`5.5` → `55`).
3. Split on `[.!?]+\s+` (sentence terminator + whitespace).
4. Restore sentinels.
5. Strip whitespace, filter empties.

**Why sentinels instead of negative-lookbehind regex**: lookbehind requires fixed-width in many engines, and Python supports variable lookbehind only in `regex` module not built-in `re`. Sentinels are language-agnostic and easier to debug.

**Why `` (SOH)**: not a valid character in any pharma text; survives `re.escape`; collisions are zero in practice.
