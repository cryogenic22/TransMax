## 1. Task

TMX-3409 added Spanish frequency patterns to `QualityGateService.check_frequency`. The `FREQ_PATTERNS` dict now covers EN + FR + ES, but every other active target pair (DE / IT / PT / KO / ZH / JA / AR) still has the false-positive class: source `"twice daily"` matches → `2.0`/day frequency; canonical target translation matches no pattern → spurious FREQUENCY_MISMATCH on every accurate translation.

Same shape as TMX-3410 but for the frequency gate instead of the numeric gate.

**Severity vs TMX-3410**: lower. TMX-3410 was a *missed* critical-safety violation (silent pass on dose tampering). This one is a *spurious* violation on canonical translations — reviewer noise, not patient risk. Still A2-relevant (deterministic gates must not produce false-positive blocks) but priority is reviewer-trust, not safety.

**Addenda**: A2 (gates must not over-fire).

## 2. Spec — acceptance criteria

- [ ] AC-1: `FREQ_PATTERNS` extended with German, Italian, Portuguese, Korean, Chinese, Japanese, Arabic patterns covering at minimum 1×/d, 2×/d, 3×/d, 4×/d for each.
- [ ] AC-2: Patterns are stored in their NFKD-folded form (e.g. German `"taglich"` not `"täglich"`, Portuguese `"tres vezes"` not `"três vezes"`) so the existing `_fold_accents` handles caller input without doubling dict entries.
- [ ] AC-3: For languages with multiple canonical phrasings (e.g. Portuguese `"uma vez ao dia"` / `"uma vez por dia"`), both forms are listed.
- [ ] AC-4: Unit tests cover a canonical-translation-doesn't-fire case for each new language and at least one tamper-fires case for two of the new languages.
- [ ] AC-5: Existing tests stay green (no regression on EN/FR/ES patterns).
- [ ] AC-6: Eval suite at 10/10 unchanged (eval is EN→ES only today; no new pairs added).
- [ ] AC-7: Ratchet stays green.

**Out of scope**:
- Pulling `FREQ_PATTERNS` into a per-language registry (refactor; Sprint 2 candidate).
- Dialect/regional variants beyond the most common form (Brazilian-vs-European Portuguese, Simplified-vs-Traditional Chinese — both forms covered where common, but exhaustive variant coverage is Sprint 2+).
- Eastern Arabic / Persian numeral handling (`٠١٢٣` etc.) — separate ticket if it becomes an active pair.

## 3. Design

Pure data addition to `FREQ_PATTERNS`. The function shape stays identical. Patterns ordered alphabetically by language code (de, it, pt, ko, zh, ja, ar) with explicit comments per language so future contributors find their language-block easily.

For Arabic specifically: stored after NFKD fold which decomposes precomposed `أ` (alif-with-hamza-above) into base alif + combining hamza, then strips the combining mark. So canonical patterns use base-alif forms.
