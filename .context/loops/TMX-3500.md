## 1. Task

The 2026-05-09 audit (`TRANSMAX_AUDIT_2026-05-09.md` §8 item 9 / §10 item 10) recommends:

> Begin the Regulatory Pack scaffold. URS, FS, IQ, OQ, PQ templates plus a generator that pulls test results plus AC traceability into a signed PDF per release. Required before any pilot SOW is signed.

For pharma deployment under GAMP 5 + EU Annex 11 + 21 CFR Part 11, every release must ship a "validation pack" — five canonical documents proving the system meets its requirements (URS, FS, IQ, OQ, PQ). Without this scaffold, the pilot SOW is unsignable.

This loop ships the SCAFFOLD — templates + generator + traceability harness. NOT signed PDFs (those are per-release artefacts owned by Programme Lead + Reg Affairs Lead + Quality Lead, per audit §10 item 11).

**Inventory (existing material to PULL, not duplicate):**
- `docs/decisions/` — 4 ADRs already exist (0001 design-philosophy, 0002 secrets-mgmt, 0003 auth-provider, 0004 revision-decision-persistence). These become FS rationale evidence.
- `.context/loops/*.md` — 50+ worksheets carry traceability (ticket → AC → test → commit). These ARE the per-ticket FS-level evidence.
- `tests/` — 95 test files. Existing test suites become OQ evidence.
- `tests/evals/` — eval harness output becomes PQ evidence.
- `ratchet/baseline.json` — quality posture metrics (17 metrics). IQ-relevant.
- `scripts/audit_worksheet_drift.py` — already parses worksheets; extract a shared helper to avoid DRY violation (Tier-2 item #11).

The scaffold's job is to PULL these together, not duplicate them.

Addenda at play:
- **A1 — Audit-by-default**: pack generation should emit a `REG_PACK_GENERATED` audit event. The v1 `AuditService` requires a `job_id`; pack generation has no job. Defer audit-event wiring to TMX-3500c when audit-v2 (TMX-3101) lands and supports null/synthetic job_id.
- **A8 — Prompt versioning**: the PQ document references prompt versions used in the eval harness. Templates leave a placeholder for this; the pack builder pulls `app/agents/prompts/*/v*.yaml` filenames if present.
- **A10 — `.context/` is the brain**: the harness reads `.context/loops/` as a primary evidence source. This canonicalises that role.

## 3. Design

Approach in three layered pieces:

**Layer 1 — Shared worksheet parser (DRY refactor first).**
Extract the worksheet parsing from `scripts/audit_worksheet_drift.py` into `scripts/_worksheet_parser.py`:
- Re-export `Worksheet`, `parse_worksheet`, `STATE_TOKEN_RE`, `IGNORE_BASENAMES` etc.
- `audit_worksheet_drift.py` imports from it (small `from ._worksheet_parser import Worksheet, parse_worksheet`).
- The traceability harness imports from it too.

This avoids duplicating ~80 lines of state-token / scaffold-handling / SHA parsing.

**Layer 2 — Traceability harness.**
`regulatory_pack/generators/traceability.py`:
- Walks `.context/loops/*.md` via the shared parser.
- For each worksheet, extracts ACs via a regex that matches `- [ ] **AC-N**: ...` and `- [x] **AC-N**: ...` (handles both the bold-double-asterisk and unbolded forms — empirically both appear in worksheets like TMX-3045).
- For each AC, attempts to find: a test file (regex match on docstring containing the ticket id, OR a path heuristic like `tests/test_<ticket-stem>.py`), and a commit SHA (the worksheet's structured `Commit:` declaration via `COMMIT_DECLARATION_RE`).
- Returns a `TraceabilityMatrix` dataclass (rows: list of `TraceabilityRow`).

The harness has ONE responsibility: read evidence, build matrix. It does NOT format markdown, does NOT call git for unrelated reasons, does NOT verify test passes/fails (that's OQ — sourced from pytest output by the pack builder).

**Layer 3 — Pack builder (orchestration).**
`regulatory_pack/generators/pack_builder.py`:
- CLI entrypoint (`if __name__ == "__main__"` + `python -m regulatory_pack.generators.pack_builder`).
- Reads each template from `regulatory_pack/templates/`.
- Substitutes placeholders: `$release`, `$generated_at` (UTC ISO), `$traceability_table` (markdown table from `build_matrix`), `$ratchet_metrics` (read `ratchet/baseline.json` for IQ), `$adr_index` (list ADRs from `docs/decisions/` for FS), `$test_count` (count from `tests/` for OQ), `$prompt_versions` (read `app/agents/prompts/` if present; else "no pinned prompts" — A8 placeholder).
- Writes to `output_dir`. Creates dir if missing. Idempotent (overwrites cleanly).
- `release` arg can be `SCAFFOLD-v0`, `v3.0-rc1`, etc.

**Templates.** Each template uses the GAMP 5 minimum content as a starting point:
- URS: Scope, Functional Reqs, Non-Functional Reqs, ACs, Signatures
- FS: Scope, Per-URS-Req design, ADR index, Risk register, Signatures
- IQ: Scope, Environment matrix (from ratchet metrics + Python version), Install verification steps, Signatures
- OQ: Scope, Test plan per FS-Req, Test results auto-pop (from pytest output captured by pack builder — for SCAFFOLD-v0 this is "deferred to TMX-3500e"), Signatures
- PQ: Scope, Performance criteria, Eval-harness results placeholder (TMX-3500e), Real-world load test placeholder (pilot), Signatures

**Alternatives considered + rejected:**
- *Use Jinja2*: rejected per ticket constraint (no new deps). `string.Template` is sufficient for placeholder substitution; no loops/conditionals needed in the templates.
- *Bake a "ticket → test" map by hand*: rejected — defeats the point of automation; would diverge instantly. The harness builds it from facts on disk.
- *Have the pack builder run pytest itself*: rejected — coupling concerns; the pack builder should consume pytest output (via a pytest --json-report or similar) but generating that is TMX-3500e. For SCAFFOLD-v0 the OQ section says "deferred" explicitly.
- *Sign the documents automatically*: rejected per addenda — A1 + Programme Lead governance. Signature blocks are empty.

**ADR**: not warranted — straightforward scaffold per audit recommendation.
