## 1. Task

The 4-agent verify-audit on 2026-05-09 raised Concern #1: **27 explicit `organization_id=DEFAULT_ORG_ID` literals remain across 13 files**, despite TMX-3012 having installed the auto-inject mixin + TenantContextMiddleware. This ticket finishes what TMX-3012b started — removing the redundant literal so that callers can no longer silently bypass the tenant boundary. Addenda at play: A3 (no silent fallbacks), A1 (audit-by-default — DLQ + audit_records writes carry tenancy from context, not from a hardcoded literal), A6 (LLM-call audit lineage relies on correct org tagging).

## 3. Design

Three phases:

**Phase A — Pipeline runner carries org_context.** `run_pipeline_background` currently spawns a fresh event loop via `asyncio.run(...)`. Per PEP 567, `asyncio.run()` snapshots the current `Context` for the new task — so ContextVars *should* propagate. But making it explicit removes the empirical-and-version-specific assumption: callers pass `org_id` and the runner enters `org_context(org_id)` itself. Cheap, unambiguous, audit-friendly.

**Phase B — Drop explicit literal at request-path sites.** Every API handler runs inside `TenantContextMiddleware` — `current_org_id()` is set. The TenantScopedMixin's `before_insert` listener auto-injects from context. So the `organization_id=DEFAULT_ORG_ID` argument is redundant. Removing it makes the tenant boundary REAL: any request that somehow bypassed the middleware (a bug we want loud) will now fail-fast with `TenantContextMissing` instead of silently writing to org `0…01`.

**Phase C — Drop explicit literal at service-layer sites.** Same logic as B, modulo Phase A: services called from background pipelines now also have org_context (because the runner sets it). DLQ + audit-record writes from `move_to_dlq` and `audit_service` will fail-fast if ever invoked outside a context — exactly the A3 invariant.

**Alternatives considered + rejected**:
- *Keep explicit literals as "belt and braces"*: rejected — duplication is itself a footgun. If middleware mutates context to a non-default org for a future per-tenant deployment, the explicit literal would silently overwrite it (preserved by the listener's "caller-provided value wins" rule).
- *Make the runner a no-op without org_id*: rejected — A3 forbids silent fallbacks. Background pipeline writes ARE regulated paths.

## 6. Red team

22-item Tier-2 checklist run against the diff (key flags only):

- **#3 — Hidden caller dependency.** `run_pipeline_background` previously had a 3-arg signature; some legacy fixture or external script could be calling it positionally. Verified: only two production callers exist (`app/api/v1/translations.py`, `app/api/documents.py`) — both updated. Zero hits in tests/, scripts/, or `__pycache__` cleared.
- **#7 — Silent fallback regression.** Worry: `current_org_id()` could return None at queue time if a request bypasses TenantContextMiddleware (e.g. an exception in middleware ordering). Mitigation: middleware is `add_middleware(TenantContextMiddleware)` BEFORE other middlewares so it always wraps; if it ever doesn't, the runner's first DB write will raise `TenantContextMissing` (loud failure, A3-correct).
- **#11 — Comment rot.** The "TMX-3012 will replace…" comments are now stale. Removed them as part of the literal removal. Audit-trail is in the worksheet + commit message.
- **#13 — Test-fixture coupling.** New tests use the shared `fresh_engine_for_db` fixture from `tests/conftest.py` (TMX-AUDIT-CLEANUP-ROUTES). No duplication of the engine-swap pattern.
- **#15 — Background task context propagation.** Verified empirically: `run_pipeline_wrapper` enters `org_context(org_id)`, captures `current_org_id()` inside `graph_app.ainvoke`, restores cleanly on exit. The full pipeline's DB writes (audit_records, scorecards, DLQ entries, segments) all transit through this context.
- **#18 — Ratchet impact.** First run flagged a `# type: ignore[call-arg]` in the new test (intentional negative test for missing kwarg). Fixed by switching to `**{}` invocation pattern, which sidesteps the type checker without a suppression comment.

A1/A3/A6 audit:
- **A1** — every state change in the pipeline still emits an audit event before any side effect; the audit_records writes still go through the chained-hash path. No regression.
- **A3** — silent fallbacks are now FEWER, not more: the pipeline writes that previously bound to `DEFAULT_ORG_ID` via a hardcoded literal now derive from caller-set context. If context is missing, the mixin raises (loud); previously, the literal would have masked the bug.
- **A6** — JobConfigSnapshot via `audit_service.capture_config_snapshot` is unaffected; org_id auto-injection runs at flush, after the existing payload construction.
