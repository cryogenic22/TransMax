## 3. Design

Playwright `page.route()` intercepts `/api/documents/**` and `/api/segments/**`, returning fixture JSON shaped to match `Segment[]` plus a `Document`. The page navigates to a stubbed-id URL; the production code consumes the stubs as if they came from the real backend.

The fixture shape mirrors what TMX-3702-v1 wired through:
```json
{
  "id": "seg-with-revs",
  "element_meta": {
    "revisions": {
      "has_insertions": true, "has_deletions": false, "has_moves": false,
      "has_moves_from": false, "has_moves_to": false,
      "authors": ["Dr. Reviewer"],
      "dates": ["2026-04-01T10:00:00Z"]
    }
  },
  ...
}
```

**Why mocked, not live-stack**: live-stack would need a real DOCX file on disk + the upload + ingestion pipeline run. Heavy. Mocked covers the page-level contract (frontend reads `element_meta.revisions` correctly and renders the pill) which is the gap.

## 6. Red team

- **CLEAN.** Tier 2 self-review:
  - Single-file test, no production code change. Risk surface = the test itself.
  - Stub fixture matches the wire shape pinned by `tests/test_segments_element_meta.py` — drift in one breaks the other, which is the right coupling.
  - The catch-all `route.fulfill({})` for any unintercepted API call prevents the test from flaking on a missing stub. It does mean an assertion that depends on a specific other endpoint will silently pass — acceptable for this scope; if a future test in the same file needs strict stubbing, it can route-replace.
  - Production failure modes:
    - `chooseHeadline` returns wrong label → assertion `toContainText(/tracked/)` fails → CI catches.
    - Page silently always-renders the indicator → assertion `toHaveCount(1)` fails (would be 2 with the no-revisions stub) → CI catches.
    - Page silently never-renders → `toHaveCount(1)` fails (would be 0).
