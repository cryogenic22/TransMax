## 1. Task

Ship an independent re-compute verifier for the v2 audit chain (TMX-3101). The chain's claim of tamper-evidence is only as strong as a verifier that can re-prove it. A writer-only world is not regulator-defensible — it merely re-emits the same hash and asserts itself.

The 2026-05-09 audit (§8 item 2, §10 item 5) lists TMX-3104 as a Sprint 2 priority. TMX-3105 (HTTP endpoint exposing this verifier) is the natural follow-up but explicitly **out of scope** here.

**Addenda at play**:
- **A1** — verifier should ITSELF emit an audit event (`VERIFICATION_REQUESTED`) when invoked; deferred to TMX-3104a to keep this loop scoped.
- **A3** — verifier never silently skips. Any unparseable row is a finding.
- **A4** — touches only audit_v2 models; never the v1 path.
- **A6** — verifier is a "qualified-supplier"-style self-check; produces evidence regulators can replay.

## 3. Design

### Data structures

```python
class EventFinding(str, Enum):
    OK = "ok"
    TAMPERED_PAYLOAD = "tampered_payload"       # stored payload_hash != SHA256(canonical_json(stored payload))
    TAMPERED_EVENT_HASH = "tampered_event_hash" # stored event_hash != recomputed event_hash
    BROKEN_CHAIN = "broken_chain"               # event.previous_hash != prior event's event_hash
    SEQUENCE_GAP = "sequence_gap"               # sequence_index skipped
    SEQUENCE_DUPLICATE = "sequence_duplicate"   # same seq twice (DB UNIQUE should catch; defensive)
    INVALID_HASH_LENGTH = "invalid_hash_length" # CHECK constraint should prevent; defensive
    GENESIS_VIOLATION = "genesis_violation"     # seq=0 but prev != GENESIS_HASH

@dataclass(frozen=True)
class EventReport:
    event_id: str
    sequence_index: int
    finding: EventFinding
    detail: str | None

@dataclass(frozen=True)
class VerificationReport:
    organization_id: str
    job_id: str | None
    event_count: int
    ok_count: int
    findings: list[EventReport]  # only non-OK entries; OK is implicit

    @property
    def is_valid(self) -> bool: ...
```

### Algorithm — `verify_job_chain(job_id)`

1. Query `AuditEventV2` filtered by `job_id`, ORDER BY `sequence_index` ASC. (TenantScopedMixin auto-filters by org.)
2. If zero events: return empty `VerificationReport(event_count=0, ok_count=0, findings=[])`. `is_valid == True` for an empty chain (no events = no claim to verify; an honest empty-job is valid). Documented choice.
3. Initialise `expected_seq = 0`, `expected_prev = GENESIS_HASH`.
4. For each event in order:
   - **Hash-length check** (A3-defensive even though schema CHECK enforces it): `len(payload_hash) != 32` or `len(event_hash) != 32` or `len(previous_hash) != 32` → `INVALID_HASH_LENGTH`, continue with stored values for downstream logic (still try to find more findings; don't abort).
   - **Sequence gap**: if `event.sequence_index != expected_seq`:
     - If `event.sequence_index > expected_seq`: emit `SEQUENCE_GAP` (gap before this event). Update `expected_seq = event.sequence_index` to continue.
     - If `event.sequence_index < expected_seq`: emit `SEQUENCE_DUPLICATE`.
   - **Genesis violation**: if `event.sequence_index == 0` and `event.previous_hash != GENESIS_HASH`: emit `GENESIS_VIOLATION`. (Do NOT also emit BROKEN_CHAIN; one finding per failure mode.)
   - **Tampered payload**: recompute `payload_hash = SHA256(canonical_json(event.payload))`. If `recomputed != event.payload_hash`: emit `TAMPERED_PAYLOAD`.
   - **Tampered event_hash**: recompute `event_hash = SHA256(DOMAIN_TAG || seq.to_bytes(8,'little') || event.previous_hash || event.payload_hash)`. (Uses STORED payload_hash and STORED previous_hash, not recomputed. This isolates "did someone change event_hash in isolation?".) If `recomputed != event.event_hash`: emit `TAMPERED_EVENT_HASH`.
   - **Broken chain**: if `event.sequence_index > 0` and `event.previous_hash != expected_prev`: emit `BROKEN_CHAIN`.
   - Advance: `expected_seq = event.sequence_index + 1`, `expected_prev = event.event_hash` (stored, not recomputed — chain walks the stored chain even when tampered, so that later events' BROKEN_CHAIN findings are correct relative to the next link).
5. Return `VerificationReport(event_count, ok_count, findings)`.

### Why two independent implementations

The verifier's `recompute_payload_hash` and `recompute_event_hash` MUST NOT import the writer's functions. Two implementations of the same spec, agreeing byte-for-byte, IS the verification. If they shared one function, the "verification" would be tautological.

Acceptable middle ground: a new `app/services/_audit_canonical.py` module shares CONSTANTS (`DOMAIN_TAG`, `GENESIS_HASH`) between writer and verifier. The constants ARE the spec; the functions are independent witnesses. Tests #1 and #10 pin this.

**Decision**: introduce `app/services/_audit_canonical.py` with `DOMAIN_TAG` and `GENESIS_HASH` only, and ALSO keep the writer's class-level constants (`AuditWriterV2.DOMAIN_TAG`, `AuditWriterV2.GENESIS_HASH`) pointing at the SAME bytes for back-compat. Verifier reads from the new module. Test #10 asserts the two function impls produce equal bytes.

Rejected alternative — full duplication of constants: would mean two independent definitions of `DOMAIN_TAG` could drift silently. We DO want the constants to drift loudly: a constants change is the spec evolving. Shared constants + independent function implementations is the right trade.

### Algorithm — `verify_org_chain(organization_id)`

1. Resolve org: explicit arg or `current_org_id()`. If both None: raise `TenantContextMissing` (A3).
2. Open one session under `org_context(org_id)` (so TenantScopedMixin filters apply).
3. SELECT DISTINCT `job_id` FROM `audit_events_v2`.
4. For each job_id, call `verify_job_chain(job_id)`.
5. Return list of reports.

### Algorithm — `verify_event(event, expected_prev_hash)`

Public API per spec. Verifies ONE event in isolation. `expected_prev_hash=None` means skip chain-linkage check (used for genesis or standalone audits). Returns `EventReport` (or `EventReport(finding=OK, detail=None)` when clean).

This is a building block. The bulk verifier walks the chain in `verify_job_chain` directly using the same logic but more efficiently (single pass with state).

### Per-event cascade — clarifying test #5

Tampering with `payload` JSON column but NOT `payload_hash` or `event_hash`:
- `recomputed_payload_hash` != `stored_payload_hash` → `TAMPERED_PAYLOAD`.
- `recomputed_event_hash` (uses stored `previous_hash` + stored `payload_hash`) == stored `event_hash` → event_hash itself is OK.
- Event N+1's stored `previous_hash` == event N's stored `event_hash` → chain link OK.

**So only `TAMPERED_PAYLOAD` fires.** The chain stays formally linked because the hashes themselves weren't touched. The payload-vs-payload_hash binding is broken. This is the most common attack class — change the data, hope no one re-hashes.

Tampering with `event_hash` column directly (test #6):
- `TAMPERED_EVENT_HASH` on event N (recomputed differs from stored).
- Event N+1's `previous_hash` no longer matches event N's NEW `event_hash` → `BROKEN_CHAIN` on event N+1.

Tampering with `previous_hash` column directly (test #7):
- Event N: recomputed event_hash uses stored prev_hash + stored payload_hash. If only `previous_hash` mutated, then event_hash was computed with the ORIGINAL prev, so recomputed event_hash (with NEW prev) != stored event_hash. So both `TAMPERED_EVENT_HASH` (because the stored hash doesn't reconstruct from stored inputs) AND `BROKEN_CHAIN` (because the stored prev doesn't match the prior event's stored event_hash) on event N.

  **Wait — re-think.** In test #7 description we want ONLY `BROKEN_CHAIN`. To produce only `BROKEN_CHAIN`, we'd need to mutate `previous_hash` AND `event_hash` consistently. But the simpler attack (mutate prev only) yields both findings.
  
  **Design choice**: emit BOTH findings in the prev-only-mutation case. The verifier surfaces every defect, not just one. Test #7 will assert: `TAMPERED_EVENT_HASH` AND `BROKEN_CHAIN` both fire on the affected event. This is honest and complete.

Sequence gap (test #8): delete event 2 entirely. Event 3 has `previous_hash = event_2.event_hash`, which is no longer reachable. The chain walker:
- Walks event 0 (OK), event 1 (OK).
- Encounters event 3 with `sequence_index=3` while `expected_seq=2`. Emits `SEQUENCE_GAP`.
- `expected_prev` is still event 1's hash. Event 3's `previous_hash` is event 2's hash (which is missing). → `BROKEN_CHAIN` on event 3.

So gap + broken chain both fire. Test #8 asserts SEQUENCE_GAP at minimum.

**Bug found during RED→GREEN**: my initial assertion `len(DOMAIN_TAG) == 20` in
`_audit_canonical.py` was wrong. The actual `b"transmax.audit.v1\0"` byte literal
is 18 bytes (17 ASCII + 1 NUL), not 20. The TMX-3101 writer docstring CLAIMS
"20 bytes" but the pinned hex digest is computed from the 18-byte literal — so
18 is the spec by test-binding. Corrected assertion to `== 18` and added a
clarifying comment in `_audit_canonical.py` documenting the writer's incorrect
docstring claim. Verifier tests then went GREEN.

This surfaces a real (but trivial) writer-docstring bug. Filed as
**TMX-3101-docstring-fix** — not blocking, since the test pins the actual
spec; the docstring is just narrative.
