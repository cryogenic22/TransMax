# TMX-3706 — PDF page-anchor → segment mapping for review highlight

**State**: `[PARKED — needs schema migration (one-way; Kapil-gated)]`
**Owner**: Document Pipeline
**Sprint**: 2 (triaged in the 10-loop maturity batch, 2026-06-11)
**Reversibility**: `one-way` — requires a new `page_number` column on the `Segment` table.

## Why parked (not shipped)
The maturity goal is to map each translated segment back to its source PDF page so the reviewer surface can highlight the right page. The data is *available* at ingestion — `app/services/pdf_ingestion.py` already captures `page_number` in each block's metadata — but the **`Segment` model has no `page_number`/anchor column** (only `order_index`). Persisting the anchor needs:

1. A new `Segment.page_number` column → an **Alembic migration** = a one-way, backend-integrity change (A4/A5). Per the autonomy model, schema changes do **not** auto-deploy.
2. The live Railway DB is built by `init_db()` `create_all`, which does **not** add columns to existing tables (TMX-DEPLOY-MIGRATE) — so the column would silently be absent in prod until that gap is closed.

## Recommendation
Bundle with the migration-strategy fix (TMX-DEPLOY-MIGRATE) and run as a dedicated, Kapil-approved schema loop: add `Segment.page_number` (nullable) + an Alembic revision, wire `pdf_ingestion` block `page_number` → segment on ingest, expose it on the segment API for the reviewer highlight. Substituted a contained two-way loop (TMX-TERMLOCK-WB) in this batch.
