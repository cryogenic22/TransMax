## 1. Task

`app/agents/graph.py:149` and `app/agents/graph.py:438` both compute the timestamp on an audit event by calling
`logging.Formatter.formatTime(logging.Formatter(), logging.LogRecord("",0,"","",None,None,None))`. That call returns
a meaningless string derived from `time.localtime(0)` — the audit event's recorded timestamp is identical
across events and unrelated to when the event happened.

Per CLAUDE.md known-issues + addendum A1 (audit-by-default) + plan E2, the fix is `datetime.now(timezone.utc).isoformat()`.

**Blast radius**: any consumer that parses these timestamps as wall-clock — currently the audit chain printout, the
audit endpoint response shape, and (in transit) the validation pack. Existing audit rows in the dev SQLite database
will continue to carry the old garbage string; no migration of existing rows is needed because (a) `transmax.db` is
about to be purged from history under TMX-3002 and (b) audit_events_v2 (TMX-3100) is the canonical table going forward.

**Addenda at play**: A1 (audit-by-default), A5 (stable IDs end-to-end — timestamps don't *replace* IDs but they're
the chronological scaffolding), A8 (regulator must be able to ask "when was this event?" and get a real answer).

## 3. Design

The fix is a one-line replacement at two sites. No design tradeoff worth an ADR.

**Why `datetime.now(timezone.utc).isoformat()` and not `time.time()` or `datetime.utcnow().isoformat()`:**

- `time.time()` returns a float epoch second; readable by machines but not by reviewers, and the audit-chain spec
  (research/design_v1.md §audit) asks for ISO-8601 strings.
- `datetime.utcnow().isoformat()` returns a naive datetime — no `+00:00` suffix — which leaves room for ambiguity
  ("is this UTC or local?"). EU AI Act technical-documentation review will flag this.
- `datetime.now(timezone.utc).isoformat()` returns `"2026-05-05T14:32:11.123456+00:00"`, unambiguous and parseable.

**Why not centralise into a helper now:** TMX-3100 (audit_events_v2 + service rewrite) is the right place to introduce
an `audit_now()` helper. Adding one ad-hoc here would mean a second refactor when 3100 lands. Keep this surgical.
