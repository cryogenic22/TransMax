## 1. Task

TMX-3201 red-team found that `app/agents/graph.py:_build_translation_prompt` and `app/agents/nodes/batch_translator.py:_build_prompt` never substituted `{{language_instruction}}` — the placeholder leaked into the LLM prompt as literal text. TMX-3201's stop-gap was to substitute empty-string. This loop wires the real value via `LanguagePackFactory.get_pack(lang).prompt_instruction`, mirroring `translation_engine.py:570-574`.

**Blast radius**: any translator call through `graph.py` or `batch_translator.py` (i.e. anything that doesn't go through `translation_engine.py`). Every call previously got an empty `language_instruction` — pack-specific guidance like "Use formal Korean (합쇼체) suitable for pharma" never reached the LLM. Fixing this changes LLM call signatures (a different prompt is sent), so the eval harness should remain at 10/10 (no LLM calls in harness-only scope) and the change ships as a behavioural improvement on real LLM jobs.

**Addenda at play**: A2 (gates run after the LLM — but a stronger LLM prompt reduces gate failures), A3 (silent placeholder leak is a quiet failure mode).

## 2. Spec — acceptance criteria

- [ ] AC-1: `graph.py` imports `LanguagePackFactory` and resolves `lang_instruction` from the target language, falling back to empty string if the lookup fails.
- [ ] AC-2: `batch_translator.py` does the same.
- [ ] AC-3: Mirror `translation_engine.py:569-574`'s try/except shape so failure modes are identical across the three call sites (defensible-supplier discipline per A6).
- [ ] AC-4: Existing tests still pass; no eval regression (10/10).
- [ ] AC-5: Ratchet stays green.

**Out of scope**: refactoring the three call sites into a shared helper. They're already a near-duplicate; a future ticket can consolidate. Doing so here exceeds TMX-3204.
