## 1. Task

The 2026-05-09 audit (`TRANSMAX_AUDIT_2026-05-09.md` §5) flagged C-08 as High severity:

> QualityGateService singleton has race-prone `_initialized` flag. Confirmed at `app/services/quality_gate.py:7-24`; no Lock in `__new__` or `__init__`.

This is the textbook **double-checked-locking-without-a-lock** anti-pattern. Two threads can both observe `cls._instance is None` (or `self._initialized is False`), both proceed to allocate / run the init body, and the second thread can publish a partially-initialised instance to its caller. The same shape exists in `_load_lang_pack` (lazy cache write under no lock).

Addenda at play: A1 (audit-by-default — quality gates feed the audit chain, so a corrupt singleton would corrupt audit-relevant defects), A2 (deterministic gates — must be reliable), A4 (the fix must not be Postgres-only or SQLite-only — it isn't; it's pure Python stdlib).

## 3. Design

**Choice: option (A) — `threading.Lock` with double-checked locking around the init guard, plus a separate `_lang_pack_lock` for the lazy pack cache.**

**Alternatives considered:**

- **(B) Module-level `@functools.lru_cache(maxsize=1)` factory**, callers use `get_quality_gate_service()` exclusively. *Rejected*: 18 callsites currently use the bare `QualityGateService()` constructor (graph.py, batch_translator.py, translation_engine.py, endpoints.py, 11 test files, 6 scripts). Removing constructor support would either (a) break all 18 callers, escalating the ticket from `two-way` to `one-way` reversibility (per CLAUDE.md gate), or (b) leave the constructor unsafe alongside a safe accessor — confusing and easy to misuse. Surgical-change discipline (Karpathy) plus the project's "backwards-compatible API additions only" rule push us to (A).
- **(C) `threading.local()` per-thread instance**. *Rejected*: defeats the singleton's purpose (the `_lang_packs` cache must be shared to amortise load cost). Also: A4 (don't deepen divergence) — multiple instances with separate caches could mask glossary/term inconsistencies under concurrent load.
- **(D) Use `__init_subclass__` or metaclass-driven init**. *Rejected*: complexity Ousterhout would call "deepening the module" without information-hiding payoff.

**Why (A) is the right choice:**
1. Public API unchanged — every existing callsite keeps working unmodified.
2. Surgical: ~25 lines added, three small surface-areas locked (singleton `__new__`, `__init__` body, `_load_lang_pack` cache write). No restructuring of business logic.
3. Double-checked locking is well-understood under CPython's memory model. The fast path stays lock-free for hot paths (>99% of calls hit the already-initialised branch); the slow path serialises only first-touch.
4. The `_lang_pack_lock` is per-instance (created inside `__init__`), so even if the singleton lock is released between `__new__` and `__init__`, the per-instance lock is created atomically inside the init body that holds the singleton lock.

**Hookable extraction.** The init body's state-setup is extracted into `_populate_initial_state()` so the thread-safety test can count exactly-once execution by patching this method (counting via a patched `__init__` would replace the very lock the test is verifying). This is information-hiding-friendly: the method is private (`_`-prefix) and adds zero public surface.

## 6. Red team

22-item Tier 2 checklist + A1-A10 audit:

- **Item #1 (deep modules / leaky abstractions)** — the lock is internal; no caller sees it. ✓
- **Item #11 (DRY)** — no existing `lazy_singleton` helper in the repo (`grep -rn lazy_singleton app/` returns 0). The same pattern is repeated in `app/services/resilience.py` (C-07) and the per-graph service caches in `graph.py` lines 29-49. **Findings**:
  - C-07 (`resilience.py`) is TMX-3052 / out-of-scope per the ticket spec — flagged but not fixed here.
  - `graph.py:29-49` has the same `if not _x: _x = X()` pattern for `_quality_gate_service`, `_db_service`, `_audit_service`. The QualityGate side is already fixed transitively (the inner `QualityGateService()` constructor is now safe), but the wrapping `graph.py` accessor still has its own race for `_quality_gate_service` reference write. **Decision**: this is a 1-line race on a module-cache write; the underlying `QualityGateService()` is now safe so the worst case is two construction calls returning the same singleton. Not worth a separate fix in this loop. Filed as **TMX-3053a** to address graph.py's cache pattern + DBService/AuditService same shape.
- **Item #15 (locking — any other shared state?)** — `_lang_packs` cache: yes, fixed. `_initialized` / `_instance`: yes, fixed. Class-level state in instance methods: none (all post-init mutation lives in `_lang_packs`). ✓
- **Item #19 (test determinism)** — the test approach (Barrier + injected sleep) widens the race window to ~50 ms, which is large enough to be deterministic on a developer laptop *and* slow CI runners. The Barrier ensures all threads start together (otherwise thread spawn delay could serialise them naturally). The patched `_populate_initial_state` is the hookable extraction — replacing `__init__` directly would have destroyed the lock under test (a real test design bug; caught and rewritten). ✓
- **Item #22 (broken windows)** — leaving `print()` in `calculate_semantic_drift` and `can_finalize` exception handlers. Pre-existing, unrelated to C-08; not touched (entropy-fight is in `quality_gate.py` rewrite — TMX-3412). ✓
- **A1 (audit-by-default)** — no audit-event change required; this is a concurrency fix, not a state-transition change. ✓
- **A2 (quality at gates, not in translate)** — fix lives in the gate service, not in the translator. ✓
- **A3 (no silent fallbacks)** — the `_load_lang_pack` exception handler already silently fell back to known packs (`ja`, `ar`); pre-existing concern, not introduced here. ✓
- **A4 (don't deepen dual-model-layer divergence)** — fix is pure Python stdlib; works identically on SQLite and Postgres. ✓
- **A5 / A6 / A7 / A8 / A9** — N/A (no IDs, no LLM calls, no IA, no prompt edits, no deletes). ✓
- **A10 (`.context/` is the program brain)** — worksheet at `.context/loops/TMX-3053.md`; `active_tasks.md` updated below. ✓
