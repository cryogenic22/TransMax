## 1. Task

The 2026-05-09 audit (§6 + Risk D) raised three operational issues:

1. **Local commit backlog** — many worksheets say `[Done, pending commit + push]`; CI hasn't validated; baseline is stale; a fresh clone cannot reproduce current state.
2. **Git index corruption** — earlier `git status` returned `error: index uses ټ͓ extension; fatal: index file corrupt`. Recoverable via `git read-tree HEAD` but indicates an interrupted command.
3. **Discipline gap** — the "end-of-loop push" pattern is not codified in CLAUDE.md, so the backlog accumulated.

This loop ships:
- A drift-detection script (`scripts/audit_worksheet_drift.py`) that any future loop / pre-commit / CI run can use to flag drift in seconds.
- Reconciliation of `.context/active_tasks.md` to match the truth on `origin/main`.
- A short push-hygiene section in CLAUDE.md so a fresh session reading the file knows the `[Done] requires SHA on origin/main` rule.
- A pre-commit advisory hook so drift surfaces locally before it surfaces in audit.

**Addenda at play**: A10 (`.context/` is the program brain — drift between active_tasks and code IS a Tier 0 entropy hit). A1 (audit-by-default — the worksheet-vs-commit chain IS a regulator-facing trust signal). A3 (no silent fallbacks — script must `exit 1` on drift, not warn-and-continue).

## 3. Design

**Approach**: a single, small, dependency-free Python script. Three steps per worksheet:

1. **Parse state** — read the file, find the `**State**:` line, normalise: `[Done] pending push` → state=`Done`, pending=True. Also scan deploy stage for a `Commit: \`SHA\`` token to capture an explicit-SHA claim if present.
2. **Resolve SHA** — derive ticket id from filename stem (`TMX-3050.md` → `TMX-3050`). Run `git log --all --pretty=format:%H %s --grep=^<ticket_id>[: ]` (Python `re.match` post-filter — git's `--grep` doesn't anchor by default). If multiple matches, take the OLDEST (the original commit, not a follow-up "fix" or "backfill" commit).
3. **Verify on origin/main** — `git merge-base --is-ancestor <sha> origin/main`. Exit-code 0 = on origin/main; non-zero = local-only.

Verdict tree:

```
worksheet state
├── Done + matching commit on origin/main → OK
├── Done + matching commit NOT on origin/main → LOCAL-ONLY (drift)
├── Done + no matching commit → MISSING-COMMIT (lying-backlog suspect)
├── Done with explicit "no code change; planning only" note → IGNORE
├── Spec / Design / WIP / Verify / Fix → IN-FLIGHT
├── Blocked → IN-FLIGHT (with reason)
└── README / template / handoff doc → IGNORE
```

**Alternatives considered**:
- (Rejected) Parse the deploy-stage commit-SHA cell rigorously and require it. Why rejected: existing worksheets have heterogeneous SHA-recording formats (some have `Commit: \`abc1234\``, some have `[x] Commit: abc1234`, some have it only in the status log). Would force a worksheet-schema rewrite, blowing scope.
- (Rejected) Make the SHA cell mandatory in `_template.md`. Why rejected: future worksheet hygiene, not this loop's concern. Spawn TMX-3061 if needed.
- (Rejected) Full-blown CI workflow with sticky comment on PR. Why rejected: the prompt says "lighter-weight is fine"; pre-commit advisory hook is enough.

**Edge cases addressed**:
- A worksheet titled `TMX-LOOP-HYGIENE` (no numeric ticket id) — script still parses by full filename stem, which works fine.
- A worksheet describing planning work that has no commit — IGNORE if the deploy stage explicitly notes "no code change; planning only" OR the state is `[Spec]`/`[Design]`. Otherwise MISSING-COMMIT.
- Windows line endings — `Path.read_text()` with `newline=None` does universal-newline translation; parsing uses `splitlines()` which handles both.
- Worksheets with multi-ticket scope (e.g. `TMX-3200-3201.md`) — the filename stem `TMX-3200-3201` gets searched; git subject `TMX-3200 + TMX-3201:` matches via the leading `TMX-3200` regex when we degrade to a shorter prefix.

**Why `git cat-file -e` is NOT the right primitive** (per red-team checklist): `cat-file -e` only verifies a SHA exists in the object database. It does NOT verify the SHA is reachable from `origin/main`. We need `merge-base --is-ancestor`. Documented in the script docstring.

### Specifically requested edge cases

- **Does the script false-positive on legitimate planning worksheets** (e.g. TMX-LOOP-HYGIENE)?
  No. Planning-only worksheets are detected via the `PLANNING_ONLY_MARKERS` heuristic ("no code change", "planning only", "planning-only") AND the classifier only triggers MISSING-COMMIT for `[Done]`-stated worksheets. A planning ticket marked `[Done]` with "no code change; planning only" in its body returns IGNORE. Currently no such worksheet exists in the repo (TMX-LOOP-HYGIENE is in active_tasks.md but no `.md` file under `.context/loops/`). When one is created, the heuristic will catch it.
- **Does the script handle Unicode / Windows line endings?**
  Yes. `Path.read_text(encoding="utf-8", errors="replace")` plus `splitlines()` handles `\r\n`, `\n`, and `\r`. Terminal output reconfigured to UTF-8 to handle `→` / `É` / `ñ` characters that appear in worksheet state lines.
- **Is `git cat-file -e` the right primitive?**
  No — explicitly rejected in the script docstring. We use `git merge-base --is-ancestor <sha> origin/main` because we need ancestry-from-origin/main, not just object existence in the local DB. A local-only commit on a feature branch passes `cat-file -e` but should be flagged as `LOCAL-ONLY`. The current implementation correctly classifies TMX-3603-agents-err as LOCAL-ONLY at first run.

## 7. Fix

Two issues surfaced during stage 5/6 and were fixed in-loop:

1. **Windows console crash** on first run (`UnicodeEncodeError` for `→`). Fixed via `_reconfigure_stdout_utf8()`. First implementation used `# type: ignore[attr-defined]` which would have tripped the `backend.type_ignore` ratchet — replaced with `getattr(stream, 'reconfigure', None)` guard.
2. **False positives via prose-commit detection** — first declared-SHA implementation matched any line mentioning "commit", causing false-positive resolutions for TMX-3614, TMX-3702-demo, TMX-3704 (which mention OTHER tickets' commits in body prose). Fixed by tightening to `COMMIT_DECLARATION_RE` which only matches structured deploy-stage lines (`Commit:`, `Code:`, `Shipped`, `Closed` + SHA).
